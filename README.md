# ETH: APT tunnel vs MEXC-style estimate

Статический сайт, две модели прогноза цены ETH, работают полностью на
клиенте (без бэкенда, без сборки) — как и ваш ETH Radar.

## Деплой на GitHub Pages

1. Создайте репозиторий (или используйте существующий, например тот же,
   где лежит ETH Radar, в отдельной папке).
2. Скопируйте содержимое этого архива в корень репозитория (или в `/docs`,
   если хотите держать его рядом с другими проектами в том же репо).
3. Settings → Pages → Source: `Deploy from a branch` → выберите ветку и
   папку (`/root` или `/docs`).
4. Через минуту сайт будет на `https://<ваш-аккаунт>.github.io/<репо>/`.

Никаких переменных окружения, ключей или сборки не требуется — все три
страницы (`/`, `/tunnel/`, `/mexc-style/`) самодостаточны.

## Что внутри

```
index.html              — страница-сравнение со ссылками на обе модели
tunnel/index.html        — ваш APT v0.8, портированный на JS
mexc-style/index.html    — наша оценка "MEXC-подобной" модели
assets/common.js         — общее: Binance-фетчеры, order-flow математика, RNG, canvas-рендер
assets/tunnel-engine.js  — порт physics_engine.py + tunnel_engine.py
assets/mexc-style-engine.js — TA + funding + sentiment + calendar факторы
```

## Adaptive Probability Tunnel (`/tunnel/`)

Прямой порт вашего Python-проекта. Та же структура (пять сил → сила и
disagreement → LPPLS-критичность → Монте-Карло по SDE `dv`/`dlogP`), то же
разбиение p20/p50/p80. Отличия и почему:

- **Данные: Binance вместо OKX.** У OKX REST API нет CORS-заголовков —
  статическая страница на GitHub Pages не может дёргать его напрямую из
  браузера. Binance публичные market-эндпоинты CORS разрешают (поэтому
  ваш ETH Radar уже на них и работает).
- **История/anchor — в `localStorage`, а не в SQLite.** Работает без
  сервера, но состояние привязано к конкретному браузеру/устройству, а не
  общее для всех, кто откроет страницу.
- **LPPLS-сетка меньше** (3×3×3 вместо 5×4×4), Монте-Карло — 1500 путей
  вместо 2500. Чисто ради бюджета CPU в браузере; сама регрессия и SDE не
  упрощены.

## MEXC-style estimate (`/mexc-style/`)

**Это не код и не воспроизведение алгоритма MEXC.** У MEXC нет открытой
спецификации Smart Chart — ни архитектуры, ни весов, ни списка фичей;
слитых данных тоже нет. Это наша собственная реконструкция "аналога по
смыслу", собранная только из того, что MEXC заявляет публично
(пресс-релизы, MEXC Learn):

| Компонент MEXC (заявлено публично) | Наш аналог |
|---|---|
| Технические индикаторы | EMA-тренд (15m/1h/4h) + RSI(14) + MACD histogram |
| "Позиционирование" / funding-подобные данные | Binance funding rate, нормализованный tanh |
| Соцсеть-сентимент (AI Strategy мониторит X) | Fear & Greed Index (alternative.me, публичный, без ключа) — не то же самое, просто ближайший бесплатный прокси |
| Календарь событий | Захардкоженные открытие/закрытие рынка США (UTC); реального макро-календаря без платного ключа с надёжным CORS нет — добавьте свой провайдер в `upcomingEvents()`, если нужно |

Дальше пять факторов сворачиваются в `force`/`disagreement` так же, как в
APT, и прогоняются через **тот же** `simulateCurrentState` — специально,
чтобы разница между двумя страницами была именно в наборе входных
факторов, а не спрятана за разным оформлением.

## Ограничения обеих моделей

- Ничего из этого не финансовый совет и не гарантированный прогноз;
  p20/p50/p80 — модельные квантили, не исторический hit-rate.
- Обе модели читают только публичные рыночные данные конкретной биржи
  (Binance) — ни ончейн-потоков, ни реальных соцсеть-сигналов, ни платных
  календарей в этой версии нет.
- Расчёт идёт в браузере пользователя при каждом открытии страницы —
  сравнивать значения на двух разных устройствах в один момент времени
  можно (входные рыночные данные одни и те же), но идентичного стейта
  (`localStorage`) между ними не будет.
